# Domain docs

Use a single-context layout: `CONTEXT.md` at the repo root and ADRs in `docs/adr/`.

Before exploring an area, read `CONTEXT.md` and relevant ADRs. If they do not exist, continue without creating them. Create domain docs when terms or decisions are settled.

Use terms from `CONTEXT.md` in issues, proposals, and tests. If a needed term is absent, check the codebase before proposing a new term.

Flag a conflict with an existing ADR rather than silently overriding its decision.
